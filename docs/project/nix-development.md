# Nix development environment evidence

Recorded 2026-10-22 for the additional U07 work unit. This is an additive delta
from Library handoff version 1, not a new product release. Candidate remains
1.0.0; completion uses an immutable work tag with the actual GitHub Issue number.

## Deeper task and completion boundary

The goal is another user's repeatable installation, operation and upgrade of the
public project. The development shell supports that goal; file presence is not
completion. Expert review checks the actual interpreter/native-wheel boundary,
lock immutability, cross-platform execution, entry/exit trust and preservation of
the independent Python install path. Primary evidence is the pinned upstream
lock/package source, actual parser/tool output and tests on each host. The method
is source comparison, syntax checks, unchanged-lock Nix realization and clean
wheel installation outside the checkout. Independent success evidence is both
Linux and macOS execution logs plus exact artifact/patch hashes. Static passes
and the earlier mini result are useful evidence, not substitutes for those runs.

## Source and design

One nixpkgs input supplies Python 3.11 and developer commands for Linux/macOS;
there is no flake-utils or remote shell-hook dependency. The Python package and
its requirements remain independently installable. `.envrc` only watches lock
files and calls direnv's built-in `use flake . --no-update-lock-file`.
No personal path, identity, key, service, implicit pip install or local secret
file is part of the flake or hook. The sdist includes these development files;
the wheel remains a normal Python distribution.

The nixpkgs lock node was copied verbatim from the official
[Nix lock at 42d96171bbef8a8073106dd93ca68878d7339abd](https://github.com/NixOS/nix/blob/42d96171bbef8a8073106dd93ca68878d7339abd/flake.lock),
retrieved from that Git commit. It selects nixpkgs revision
`c3eea5b2156db11c7eeeada3dc737711255b253e`, release archive
`nixos-26.05.9729.c3eea5b2156d`, NAR hash
`sha256-it+7kNGnOOHBCEnl4SfZ7QtfGziH3EryzHqwvJpjAfg=`.
The input's original URL is the same nixos-26.05 channel as upstream; the locked
URL is immutable. Updating requires an explicit lock change. This lock was
assembled from verified upstream data, **not generated by a local Nix run**.

Source review at that nixpkgs commit finds Python 3.11.16, direnv 2.37.1 and
Gitleaks 8.30.1. These are source declarations, not executed local versions:
[Python](https://github.com/NixOS/nixpkgs/blob/c3eea5b2156db11c7eeeada3dc737711255b253e/pkgs/development/interpreters/python/default.nix),
[direnv](https://github.com/NixOS/nixpkgs/blob/c3eea5b2156db11c7eeeada3dc737711255b253e/pkgs/by-name/di/direnv/package.nix),
[Gitleaks](https://github.com/NixOS/nixpkgs/blob/c3eea5b2156db11c7eeeada3dc737711255b253e/pkgs/by-name/gi/gitleaks/package.nix).

The CI installer is pinned at
[cachix/install-nix-action 448cde739abec1eaf0646249e3d25bb8d9bc7702](https://github.com/cachix/install-nix-action/tree/448cde739abec1eaf0646249e3d25bb8d9bc7702),
with explicit official Nix 2.35.3 installer URL. The installer runs only in
disposable GitHub runners; KVM changes and extra trusted-user configuration are
disabled. Source/action pins do not freeze the hosted OS image. The workflow
must run on its actual proposed commit before being called successful.

The design follows the official [Nix lock/evaluation semantics](https://nix.dev/manual/nix/2.28/command-ref/new-cli/nix3-flake-check),
[direnv standard library](https://direnv.net/man/direnv-stdlib.1.html), and
[GitHub runner architecture table](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

## Initial cloud evidence and execution limits

- Cloud has no `nix` or `direnv` executable. No system installation was attempted;
  no directory was trusted with `direnv allow`.
- Downloading the locked release archive from releases.nixos.org returned HTTP
  403 in this environment. The NAR hash is independently sourced above but was
  not recomputed here. Local Nix evaluation/build therefore remains unexecuted.
- `flake.nix` passes tree-sitter-nix 0.1.0 parsing with tree-sitter 0.26.0. This
  verifies syntax only, not Nix evaluation, package availability or realization.
- Bash syntax and workflow YAML are checked separately. Exact source/lock
  comparison and post-change Python/build/install results are recorded in
  [validation](validation.md).

Acceptance is pending until `nix flake check --no-update-lock-file` and
`scripts/check_nix_environment.sh` succeed through `nix develop` on Linux and
macOS, and the lock is unchanged. The workflow covers x86-64 Linux and arm64
macOS. The declared arm64 Linux and Intel macOS outputs are unverified.
An approved host must additionally exercise direnv entry/exit and confirm the
selected interpreter; do not treat a syntax check as permission for local trust.
CI grants trust only in its disposable environment. Host-level installation or
trust decisions stay with the operator; this delta does not install either tool.

## Subsequent macOS arm64 execution

On 2026-10-22, the complete Nix-amended candidate passed actual archive/NAR
verification, `nix flake check --no-update-lock-file`, and the locked Python
3.11.16 development shell. All 64 source tests passed with official installed
Buzz ACP, followed by build, isolated wheel acceptance and secret scans. The lock
was unchanged. These results apply to the amended candidate, not only its earlier
non-Nix version.

Developer-host `direnv allow` was not executed. Linux Nix execution and disposable
CI direnv entry remain remote workflow gates. The other declared architectures
are not validated by this macOS arm64 result. Python 3.14 is not an accepted
development target because its dependency build failed during earlier evaluation.
